# Changelog

All notable changes to the Granergize WebApp project will be documented in this file.

## [2026-06-05]
- Demo buildings are now offered, not silently written: on a fresh Pod (no `buildings/` container) the app no longer auto-seeds two example buildings — instead a dismissible info **banner** ("No buildings yet — add a couple of example buildings to explore?") offers **Add examples** / **No thanks**, with the decline remembered in `prefs.ttl` (`gran:demoSeedDeclined`) so it doesn't nag. An avatar-menu **"Create demo buildings"** adds them on demand. And **"Remove all app data" no longer forces a logout** — it stays in the now-empty app, resets the query caches, and re-offers the demos (the forced logout only existed because startup used to re-seed the just-deleted data). The banner is non-blocking, so it doesn't get in the way of adding your own buildings
- E2E: collapse the `sharing` and `view-sharing` specs from 4-/6-part multi-process splits into a single test each, driving two browser contexts (A and B) in-process. The split only ever existed to stay under solidcommunity.net's Cloudflare burst limit; on the reliable Pods it's unnecessary, so the gitignored state-file handoff and the `-g "part N"` choreography are gone. A 2 s cooldown sits at each write→read handoff. Both are now fully self-cleaning in `finally` (A deletes its building/view + room, and B drops its bookmark of A's room via a new `removeAllBookmarkedRooms` helper). Also made `building-delete` and `energy-entry` self-cleaning (add-then-delete their own building rather than consuming/mutating a seeded one), and `provenance` restores the prior profile role in `afterAll`
- Building coordinates are now a `geo:Point` blank node carrying their geocoding precision, instead of flat `geo:lat`/`geo:long` on the building: `<#b> geo:location [ a geo:Point ; geo:lat … ; geo:long … ; gran:geocodePrecision … ]`. `gran:geocodePrecision` is IRI-valued (`gran:Address` / `gran:Postcode` / `gran:City`) and records how precise the lookup was, so an approximately-placed building (only its city resolved) is distinguishable from a rooftop hit. Both write paths go through one helper — `serializeBuildingToTurtle` (new buildings) and `updateBuilding` (edits, which migrates a legacy flat-coordinate building to the point on save); the parser prefers the point but still reads legacy flat coordinates as a fallback, so existing Pods and fixtures aren't orphaned. New `geo`/precision constants in `vocabularies.ts`; adds unit tests (point + precision written, not flat, round-trips; legacy flat still parses)
- Importing a building template now geocodes it on import (PROBLEMS.md #6): the investor/BSP templates carry an address but no coordinates, yet lat/long are required, so a bulk import previously couldn't be submitted at all. `handleFileUpload` now resolves each parsed building's coordinates via the shared `geocodeFields`, which tries progressively coarser queries (full street → postcode + city → city) so a too-precise house number a geocoder can't place still yields an approximate pin (recording the matched precision, see above), throttled to Nominatim's ≤1 req/s. `geocodeFields` is exported from `buildingSerializer` and now backs the demo seed and BOTH the Add and Edit dialogs' "look up coordinates" buttons (was the same Nominatim call copied in three places). Also fixes a real accessibility defect surfaced by the e2e: the Add dialog's `Template` `<Select>` (and the `enumSelect` helper) had no `labelId`, so it had no accessible name — `getByLabel("Template")` and screen readers couldn't find it
- E2E: make `excel-upload` reliable and self-cleaning — it stubs Nominatim with deterministic coordinates (an e2e must not depend on a rate-limited third-party geocoder), polls the Manage list for the post-import refetch instead of reading it once, accepts the `Delete building` `window.confirm`, waits for each building's row to vanish rather than the lingering "Building deleted" toast (which let the cleanup loop race and leak buildings), fills location fields for the address-less Lastgang file, and no longer depends on demo seeding. `data-room-switch-debug` gains an `afterAll` cleanup net (the shared `deleteAllOwnedRooms`) so a mid-switch timeout — its common failure — can't leak the rooms it hosts
- Building provenance is now set once in your WebID profile, not chosen per add (PROBLEMS.md #1 / Handbuch HW5 — **Done**): a "data-producer role" stored as W3C `org:role` on an `org:Membership` (`organizationManager.ts` `get`/`saveProducingRole`), set in the Organisation dialog and applied automatically as `prov:hadRole` on every building you add (`AddBuildingDialog` reads it via `getProducingRole`). The Add dialog's Template selector is now spreadsheet-shape only; unset role → no attribution is written, with an inline nudge to set one. Finishes separating `UserRole`'s three jobs (template / provenance / data-room role). Adds a round-trip unit test and a `provenance` e2e (set role = Investor, add a building with the *User* template → it filters under Investor, not User, in Create View)
- Aggregated-view revocation now notifies the recipient (PROBLEMS.md #21, the view half — building revocation already did): `revokeViewAccess` posts an `interop:AccessRevocation` to the recipient's inbox (best-effort, via the now resource-neutral `notifyAccessRevoked`), so on their next inbox drain the view folds out of `shared-in/` and disappears from "Views shared with you" — instead of lingering with values that no longer load. Deleting a shared view is covered too: `useDeleteView` revokes (and notifies) every recipient via `revokeAllViewRecipients` before deleting the snapshot, so it doesn't leave a stale row either.
- Aggregated-view sharing now has a recipient side (PROBLEMS.md #17): a view shared with you appears under a new "Views shared with you" section on the Share tab and opens to its computed values (a table + the same SVG bar chart the owner sees). Previously the `kind:View` grant reached your `shared-in/` log but nothing surfaced it — `getSharedViews` was sender-only, `SharePage` listed only buildings, and `/#/view/:id` resolved against your own Pod. Adds `getReceivedViews` (folds `shared-in/` for `View`, mirroring `getSharedWithMe`), `useReceivedViews`, a login-time invalidation, and renders the snapshot via the existing `loadComputedSnapshot`. Adds a two-pod `view-sharing` e2e covering the full lifecycle (A hosts a room → B joins → A creates+shares a view → B sees it + values render → A deletes the view, revoking B → B no longer sees it), plus unit tests for the fold
- E2E: add `excel-export` (PROBLEMS.md #8) — asserts the browser download fires with the expected filenames (`buildings-mine.xlsx` / `building-<id>.xlsx`) and that an exported workbook re-imports to the same buildings (full round-trip through Add Building's file picker, then deletes the copies). Destructive; expects a reseeded Pod
- E2E: a shared `deleteAllOwnedRooms` helper (`e2e/helpers/rooms.ts`) lets a spec delete the data rooms it hosts in a final cleanup part, so the `sharing` and `view-sharing` runs no longer leak rooms on the Pod across runs
- Decouple "Add Building" from data-room roles (PROBLEMS.md #1, one more step): adding a building to your own Pod no longer requires holding a self-assigned role in a data room. The Add dialog's selector is now a plain import **template** chooser (always populated; the old "You have no role assigned in the data room…" dead-end and the disabled "Add Building" button are gone), finishing the half-done Role→Template rename in the UI (`AddBuildingDialog.tsx`). Data-room roles stay purely a *sharing* concept; the chosen template is still recorded as the building's PROV provenance category (binding provenance to the WebID profile instead remains the open part of #1). The `excel-upload` e2e drops its room-role skip and selects the template directly
- Keep the map's building detail pane view-only: the two write actions that had leaked into it — "Upload/Replace energy certificate" and "Add / edit energy year" — move to the Manage tab as per-building row actions (next to Edit / Share / Download / Delete), where outgoing-data actions belong. The standalone `/building/:id` page (unreferenced in the app) drops them too, and `Building` no longer needs a `session` prop
- Manage: move "Download all (Excel)" up next to the buildings collection URI (the `buildings/` RDF source link), out of the bottom Add/Autofill button group
- E2E: `energy-entry` now opens the per-year energy dialog from the Manage row action (was the standalone building page)
- E2E: add `building-delete` (PROBLEMS.md #3) — adds a throwaway building, asserts it appears on Manage, then deletes it via the "Delete building" row action and asserts the row is gone and the count is back to the start. Self-cleaning (adds + deletes its own building)
- Excel import is now cancellable (PROBLEMS.md #6 → Partial): the Add-building upload threads an AbortSignal through `writeBuildingEnergy`/`uploadBuilding`, and the busy overlay shows the live requests + a "Cancel upload" button (cancel aborts between writes; fully-written buildings are kept). Adds an `excel-upload` e2e (import an investor template + cancel a long 15-min upload) and an offline unit test for the abort. Still open: the upload is slow for a 15-min year (~365 daily files), and there's no deferred/background upload
- PROBLEMS.md: mark #5 (update/add a consumption year) and #15/#16 (Soll-Ist planned-vs-actual) **Done** — shipped by the energy-redesign's per-year entry form + planned scenario and the investor/BSP overlay charts (e2e `energy-entry`, unit `MetricBarChart`/`energyDataset`); #17 (share a single year) nudged to **Partial** (each year is now its own shareable resource at the data layer, but the share UI still offers only the two building-level levels). Record the spec/test coverage for the fixed items
- Fix received shares never appearing: on login, `readInbox` builds a Pod path (`shared-in/`) via the synchronous `getStorageRoot`, which threw "Storage root … not resolved" because the inbox drain ran *before* the storage root was resolved — so the grant was never archived and the recipient's "Buildings shared with you" stayed empty (with only a transient error toast). `handleLogin` now resolves the storage root before draining the inbox
- Errors are observable, not just transient toasts: `showNotification` mirrors error/warning notices to `console.error`/`console.warn` (`[notify] …`), and the "Could not locate your Pod storage" gate failure does too — so failures show in devtools and can be caught by tests, instead of a snackbar that auto-dismisses before anyone (or Playwright) sees it
- E2E: a shared error guard (`watchAppErrors`) collects those `[notify]` console errors + uncaught page errors and fails a test with the real message instead of a bare "element not found" timeout (wired into `sharing`); `sharing`'s room-URI helper repointed to the new Connect active-room link (the old "URI:" paragraph is gone)

## [2026-06-04]
- Charts: migrate from Chart.js (`react-chartjs-2`, opaque `<canvas>`) to Recharts (SVG) across all five energy charts — the per-building investor/BSP annual bars (incl. the actual-vs-planned Soll-Ist overlay), the categorical energy-need view, the 15-min user series (day / daily-totals / average-profile), and the aggregated-view chart. Two shared helpers (`MetricBarChart` / `MetricLineChart`) back them, so bars/axes/legend are now real DOM that Playwright can assert (the `energy-smoke` and `energy-entry` e2e now check the SVG surface + a drawn bar/line instead of "a canvas exists"). Removes `chart.js`/`react-chartjs-2`, the `chartSetup.ts` global registration, and the Vite chart-dedupe plugin/chunk plumbing
- Energy-model redesign — one `gran:EnergyDataset` per (building, year, granularity, scenario), linked by a single `gran:hasEnergyDataset` predicate (implements notes/energy-redesign.md). Replaces the three fragmented representations (`investor:hasInvestorAnnualData` inline annual, `gran:hasEnergyMeasurementData`, `gran:hasEnergyConsumptionDataset`) and two metric vocabularies with unified `gran:` metric IRIs (`ElectricityConsumption`/`HeatConsumption`/`WaterConsumption`/`WastewaterConsumption`/`RenewableSelfGeneratedShare`). Each year is its own resource (annual = inline `sosa:ObservationCollection` in `<year>-P1Y.ttl`; 15-min series = a located descriptor `<year>-PT15M.ttl` → daily files under `<year>-PT15M/`), so a year can be added, edited and shared on its own; the self-describing `<year>-<granularity>[-planned]` slug lets the loader dispatch (annual prefetched, series lazy) without a fetch. Migrated the writer/seed, parser, `loadEnergy` (map panel + averages), the per-building charts (annual investor/BSP + 15-min series), the aggregated-Views computer, building sharing/revocation (grants the dataset files + a series' daily-files container), and the Excel export. Adds a per-year energy entry form (avatar-style "Add / edit energy year" on a building) that writes one dataset per year and supports both **actual** and **planned (Soll)** figures, with the investor/BSP charts overlaying planned beside actual (Soll-Ist comparison). Also reconnected the Energieausweis (energy-certificate PDF) upload, which had lost its trigger. Adds an `energy-smoke` e2e
- Storage redesign — a container-native, event-log Pod layout (implements notes/storage-redesign.md). Replaces the flat registry files with: personal state in `prefs.ttl` (active room + hidden buildings) and `bookmarks.ttl` (external rooms); own buildings discovered by **listing** `buildings/` (demo-seeded only on a genuinely fresh Pod); aggregated views as one resource per view (`views/<id>.ttl`) plus shareable snapshots under `views/snapshots/`; and sharing as two append-only event logs — `shared-out/` (sharing performed) and `shared-in/` (sharing received, archived from the inbox) — folded to current state (a later revocation drops a grant), with the WAC `.acl` remaining the enforcement truth. Removes `dataSources.ttl`, `rooms.ttl`, `hiddenBuildings.ttl`, `sharingRegistry.ttl`, `views/viewSharingRegistry.ttl`, `views/viewDefinitions.ttl` and the unused agents data source. One Turtle shape now serves the inbox message and both logs. No migration: a Pod is wiped (Clear app data) and re-seeded into the new layout
- E2E: add `storage-smoke` and `energy-smoke` Playwright smokes (account B on solidweb.org) that open a freshly-seeded Pod and assert the new container-native storage layout and the unified energy-dataset model render end-to-end (own buildings listed, views/shared-in folded, a room hosted+deleted; a building's `/energy/:id` chart draws). Both expect a wiped+reseeded Pod. Document running the credentialed suite with `--workers=1` so parallel Solid logins don't trip the Cloudflare rate limiter (the config doesn't pin a worker count)
- Add solidweb.org as a login identity provider (now listed first)
- Data rooms: switching the active room back and forth is now reliable (it could revert on slow/throttled storage)
- Regenerate the in-app guide screenshots (new login wording, basemap.de map, renamed tabs) and capture the login screen
- Add E2E tests for the data-room lifecycle (host / enter / leave / switch / delete); unit tests for the dialog close-guard, optimistic room state, and error formatting
- Record building-data provenance with W3C PROV (a qualified attribution to the producing agent) instead of the ad-hoc data-source "role" — the role no longer drives behaviour: energy loads and renders by the data's declared granularity, and map markers distinguish only owned vs shared (not the producer)
- Rename the add/import "role" selector to "template" (it chooses the spreadsheet shape, not your identity); operating costs and building certifications now round-trip through both Turtle and Excel (previously read but never written)
- Building data export is Excel (.xlsx) now (was Turtle) on both Manage and Share, plus a "Download all" that produces a single workbook (one row per building)
- Docs: rewrite CLAUDE.md (React Query data flow; roles → PROV provenance), refresh notes/ for the PROV model, and update PROBLEMS.md (mark "delete a building" done; note the role/marker and provenance changes)
- Add design notes for a planned container-native Pod layout with event-log sharing (notes/storage-redesign.md) and a unified energy-dataset model — one dataset per building/year/granularity (notes/energy-redesign.md)
- Internal: the room registry uses optimistic cache updates + conditional (If-Match) writes with an authoritative current-room pointer (fixes the switch revert); read the WebID profile/inbox once on login (was twice); shared helpers for recipient-inbox lookup and XLSX export; remove dead code
- Login recovery: the "Could not locate your Pod storage" error screen now offers a "Back to login" button (it was a dead end), and a 15s timeout turns a hung storage lookup into that escapable screen instead of an endless spinner; the login screen likewise no longer traps you on "Loading…" if a redirect/restore stalls
- Switch accounts at the same identity provider: a new avatar-menu "Switch account…" logs you out at the provider too (not just the app), so it stops silently re-authorising the same account
- Add solid.redpencil.io as a login identity provider
- Login screen layout: wrapped in the app's outlined card surface (wider, h5 title), even section spacing, both provider lists as vertical stacks, `subtitle2` section labels, the Granergize@FAU · Granergize@IIS links moved to a centered footer, and natural page scrolling when the card is taller than the viewport

Threads an AbortSignal through the recursive delete; adds offline tests for aborting before and mid-run
