- **The account actions join the query/mutation model — "every user-intent Pod write goes through a mutation hook" is now total, and read-intents become a named category.** The dashboard's six account actions were the last hand-rolled handlers (bespoke busy flags, manual `formatError` toasts, call-site invalidations in `index.tsx`): demo-buildings seeding, remove-all-app-data, archive download/restore, the sharing audit and the ACL rebuild. Each is now a hook (`useSeedDemoBuildings`, `useRemoveAppData`, `useExportArchive`, `useRestoreArchive`, `useAuditGrants`, `useReissueGrants`) owning execution, `isPending` busy state, the central `meta.action` error toast and its invalidations; the call sites keep exactly the UI these intents need beyond that shape — the computed-preview confirms (`listContainedResources` / `inspectArchive`), the full-page `ActivityScreen`, and outcome rendering (tally toasts). Notable shapes: `useRemoveAppData` follows the `useUploadBuildings` abort-as-OUTCOME pattern (`{aborted: true}`, never an error) and settles with `qc.clear()` — fixing a real gap where an aborted/failed wipe left every query cache stale over a partially-deleted Pod (the page drives post-success flow from the `mutateAsync` continuation, since the clear takes the mutation cache with it); `useRestoreArchive` folds the ACL rebuild into the restore intent (the archive carries the log, not the derived `.acl`s) and invalidates everything; `useReissueGrants` deliberately invalidates nothing (the ACL projection is no query's input). The two read-only actions are **imperative READ-intents**: queries per CQS (`@operation query`, zero Pod writes — pinned by test) that wrap the `useMutation` primitive purely as the on-demand trigger, NOT `useQuery` — an audit must re-read the Pod per click, a cached one would report stale consistency. Error-wording deltas from the central phrasing: "Failed to restore the archive / download the archive / remove app data: …". Docs: `notes/read-write-operations.md` gains the §Account-scope operations classification (seeders = user-intent Model-2 bulk creates with commit-last ordering and tally outcomes; the wipe = terminal in-place mutation spanning all models' artifacts; restore = Model-2 bulk write with embedded reconciliation) and the subscription-vs-read-intent split on the query side; `notes/app-intents.md` updated (the boundary cases are folded; the read-intent category existed unrecognized in the reads-are-declarative/writes-are-imperative blind spot). **Tests:** six new hook cases — seed tally + buildings invalidation pin; wipe end-to-end against a fake Pod with the outcome-survives-`qc.clear()` pin; cancelled wipe resolves `{aborted: true}` AND still resets the cache; restore round-trip over real `exportArchive` bytes (+ invalidate-all pin); export/audit read-intents return results with zero Pod writes and zero invalidations; reissue zero-counts on an empty log.

- **Energy years written after a share now extend the grant: `reconcileBuildingGrants` in the write path (QUESTIONS.md gap closed, pinned check flipped).** A grant event records an *intensional* scope ("this building, all energy years") but its ACL projection is *extensional* (per-dataset `.acl`s enumerated at apply time; `energy/` deliberately carries no acl:default so per-year grants stay enforceable) — so a `writeEnergyYear` after the share produced a dataset the recipient silently 403'd on. Now the write-energy-year mutation runs `reconcileBuildingGrants(buildingFile, session)` after the save: fold `shared-out/` (cheap — the immutable-event cache makes a re-fold ~the container listing), re-apply each ACTIVE grant on that building per its *recorded* scope via the shared `buildingGrantTargets` enumeration — an all-years grant picks up the new dataset, a per-year grant correctly leaves it outside, an unshared building folds to zero and writes nothing. Record-free like the replay (no log append, no inbox post — the logged event already covers the scope, replayability untouched), idempotent, and **best-effort in the hook** (the year is already saved when it runs, so a throttled ACL write must not fail the save; the resulting residual drift is exactly what `auditGrants` detects and `reissueGrants` repairs). The third member of the reconciliation family (`notes/read-write-operations.md` §trigger — one that lives inside another mutation). **Tests:** unit — all-years grant extends to the post-share dataset (audit-clean after) and stays record-free, per-year scope leaves the new year ungranted, revoked pairs / other buildings / views reconcile to zero writes; hook — `useWriteEnergyYear` against a fake Pod with a seeded grant event asserts the new dataset's `.acl` gains the recipient; Tier-2 — `grant-projection`'s pinned KNOWN-GAP check FLIPPED: the app write path is readable by B immediately + audit-clean, and the repair leg survives via a bare service write standing in for a failed best-effort reconcile (drift → pinpointed → replayed → clean). Unit 438/0, lint + build green, Tier-2 64/0.
- **`auditGrants` — the dry-run diffing twin of `reissueGrants` (+ dev-mode "Check sharing consistency").** The repair could fix log↔ACL drift but never *show* it: a rebuild that rewrote 40 correct `.acl`s and one missing grant looked identical to a no-op, and you had to mutate the Pod to learn anything. `auditGrants(session)` (a query) folds `shared-out/` like the repair, computes the expected projection, reads the actual `.acl`s back (`hasReadGrant`, the read-side mirror of `writeAuthorization`'s shape), and reports the diff in both directions — `missing-grant` (a share whose ACL write failed; the post-share `writeEnergyYear` year) and `lingering-grant` (a revocation whose withdrawal failed) — with no writes. Same scope rules as the repair: off-Pod skipped, deleted resources `missing` not drift, out-of-band agents unreported, self-grantee revocations not flagged (the lockout guard never withdraws the owner). One source of truth for "what a grant covers": the enumeration is extracted as `buildingGrantTargets` (building file, `files/` container incl. acl:default, legacy cert, energy datasets per recorded scope) and `applyBuildingGrant` now writes exactly that set, so apply and audit cannot disagree. Surfaced dev-mode next to the rebuild as "Check sharing consistency": success toast with the pair count when clean, warning with the drift count (pairs detailed on the console) pointing at the rebuild when not. **Tests:** unit — an event-without-ACL pod reports all expected targets missing (per-year scope honoured: the out-of-scope year is NOT drift), audit-clean after `reissueGrants` (post-repair verification), lingering revoked recipient flagged while the active one isn't, deleted resource = `missing` not drift, no-writes asserted throughout; Tier-2 — `grant-projection` now double-checks every leg owner-side with full pair coverage (clean at share time, exactly the one missing-grant while drifted, empty after repair). Unit 434/0, lint + build green, Tier-2 62/0.

- **Four small deferred follow-ups from the review cycle.** (1) **Immutable-event cache inside the fold** (`sharingLog.ts`): a sharing-log event resource never changes once POSTed (append-only container, server-minted IRI), so its parse is now cached per Session (`WeakMap`, so a re-login or a test's fake session never sees another's entries) — a re-fold costs only the container listing plus GETs for events not seen before, instead of one GET per event every time. Only non-empty parses are cached: `readStoreOrEmpty` degrades a transient 403/throttle to an empty store, and that must stay retryable. The natural sequel to the fold dedup: that made it 1 fold per load, this makes each fold after the first cheap. (2) **One prefs read per load**: `loadBuildings` took its hidden-buildings set via its own `readPrefs` GET although the `prefs` query already had it — the set is now a parameter (mirroring `sharedSources`), `useBuildings` depends on `usePrefs` and keys on the hidden fingerprint, and `fetchAndParseData` reads prefs once itself (concurrent with the fold) for the headless tier. The visibility toggle now invalidates ONLY `prefs` — the buildings refetch falls out of the key change (the old extra `buildings` invalidation would double-load).
